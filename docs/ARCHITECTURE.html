PowerBI-LLM Streamlit + Anthropic Claude + Power BI MCP Server

把 Power BI 的重复劳动，交给 Claude。

一个 Streamlit 应用，三个 tab —— 把过去靠人手写文档、手添 README、手写 DAX 才能搞定的事，全程由 Anthropic Claude 驱动。

3 个 tab 2 个 Claude 模型 1 个 MCP server 输出语言 EN / FR / ZH
01 · 使用场景

解决 Power BI 工作里的三类日常痛。

每个 tab 对应一种典型场景。三个 tab 相互独立，按需使用 —— 不写 DAX、不开 Power BI Desktop，浏览器里就能搞定。

01
Documentation · Claude Sonnet 4.6

给报告自动生成完整文档

给 Power BI 报告手写文档既费时间又难以保持更新，每个团队的格式还都不一样。等报告改了几版，文档基本就废了。

上传一个 PBIP .zip，工具解析里面的 report.json 和 model.bim，让 Claude Sonnet 4.6 把每个 page、每张 table、每个 measure 都讲清楚，最后拼成一份完整的 Markdown 文档。

输入
PBIP .zip
输出
Documentation.md · 可下载 + 在线预览
Sonnet 4.6 Markdown EN / FR / ZH
02
README · Claude Sonnet 4.6 · multimodal

给报告内部加一页 README

Power BI 报告本身没有 README 页面。使用者打开后，看到一堆图表却不知道这个看板是干嘛的、应该怎么用。

同时上传 PBIP .zip 和报告的 PDF 导出。PyMuPDF 把 PDF 每页转成 PNG，Sonnet 4.6 多模态同时看 JSON + 截图，写出一页 README 并注入到 report.json 里，最后重新打包成 zip。

输入
PBIP .zip + 报告 PDF
输出
modified_pbip.zip · 用 Power BI Desktop 重新打开就能看到 README 页
Sonnet 4.6 multimodal PDF → PNG
03
Chat · Claude Haiku 4.5 · MCP

对着实时模型用自然语言问问题

想知道某个 measure 怎么算的、两张表怎么关联，平时要么打开 Power BI Desktop，要么自己写 DAX —— 没有一个对话式的入口。

在 sidebar 里填好 Fabric XMLA 端点和认证方式（interactive 或 username+password）。Claude Haiku 4.5 通过 Microsoft 官方的 Power BI Modeling MCP Server 直接查询你的实时模型 —— 它不是猜，是真的去问。聊天历史只存在 session 里。

输入
自然语言问题
输出
自然语言回答 + 每次 tool call 的明细日志
Haiku 4.5 MCP · stdio Fabric XMLA
02 · 技术框架

只跑 Python，对外只跟两个服务说话。

整个系统没有前端框架、没有构建步骤、没有数据库。 Python + Streamlit 在本地跑起来，对外只通过 HTTPS 调 Anthropic API，通过 stdio 跟 Microsoft 提供的 MCP server .exe 交互。代码按职责切成 6 层，每层只做一件事。

整体通信图

浏览器 ↔ Streamlit 走 HTTP / WebSocket；Python ↔ MCP server 走 stdio；MCP server ↔ Fabric 走 XMLA over HTTPS；Anthropic 走公开 HTTPS API。

六层代码结构

每个 layer 都是一个独立的 folder，只负责一件事。点击展开看里面的文件。

  • 应用入口。创建 3 个 st.tabs(...)，对每个 tab 做输入校验，时机合适时实例化 Anthropic client，然后调用 handle_documentation_generation / handle_readme_generation / tab_chat.render。
  • 所有 sidebar 输入集中在这里：API key、输出语言、PBIP zip、PDF，以及一个可折叠的 "Chat connection" 面板（XMLA 端点、认证方式、可选的 MCP exe override）。返回一个 SidebarValues dataclass。
  • Chat tab。负责管理 st.session_state.chat_history，重放历史对话，渲染每条消息的 tool-call 折叠面板，并在每次用户提问时调用一次 claude_agent.run_agent。
  • Documentation tab 的顶层编排。调用 extract_report_and_model 解 zip，再实例化 DocumentationTabHandler 跑文档生成，最后把 Markdown 同时作为下载和在线预览呈现。
  • README tab 的顶层编排。先解 PBIP zip，再把 PDF 每页转成 PNG，跑 ReadmeTabHandler，最后通过 write_modified_zip 把改动后的 JSON 重新打包成 zip。
  • 对 Anthropic SDK 的两层薄封装：call_text() 跑纯文本对话，call_with_image() 跑多模态（base64 编码 + 自动识别 png / jpeg / webp / gif 媒体类型）。默认模型 Sonnet 4.6。
  • 定义抽象类 TabHandler，以及 HandlerRequest / HandlerResponse 两个标准化的输入输出 dataclass。整个项目的可扩展性都靠这个抽象 —— 加新 tab 一律是 subclass，不是改老代码。
  • Documentation tab 的 TabHandler 实现。把每页摘要、表摘要、measure 总览、measure 详情拼成最终 Markdown 文档。
  • README tab 的 TabHandler 实现。走多模态摘要路径，准备 README 参数，最后返回改写后的 report.json 字符串。
  • 所有 prompt 模板 + Claude 调用的工具函数：summarize_dashboard_by_page、global_summary_dashboard、summarize_table_source、create_measures_overview_table、多模态版本 summarize_dashboard_by_page_png_json，以及 prepare_readme_arguments。
  • 把 MCP server 拉起来作为 stdio 子进程。专门解决 Streamlit event loop 冲突 —— Streamlit 主线程已经有 event loop，这里把每次 async 调用单独放进一个新线程跑自己的 fresh asyncio loop。INIT_TIMEOUT = 120s（首次启动 .NET single-file app 要自解压），TOOL_TIMEOUT = 60s。MCP server 的 stderr 被重定向到 /dev/null，避开 Windows pipe 的坑。
  • 根据 FabricCredentials 拼 OLE DB 连接字符串（支持 interactive 浏览器登录、username+password 两种认证方式），再调 MCP server 的 connection_operations 工具。Service principal 认证在 UI 里有意没开放。
  • tool-use loop 的核心。每次 run_agent() 调用只开一次 MCP session（保证连接状态在多次 tool call 之间保持）。硬上限：MAX_ITERATIONS = 6、max_tokens = 4096。只把 7 个只读 tool 暴露给 Claude —— model_operations、table_operations、column_operations、measure_operations、relationship_operations、dax_query_operations、security_role_operations。第 8 个 connection_operations Python 自己用，不给 Claude 看。工具 schema 在首次 list_tools 后进程内缓存。
  • EN / FR / ZH 三种语言版本的 chat system prompt。明确告诉 Claude：用 MCP 工具去查，不要瞎猜。
  • extract_report_and_model 把 zip 解到临时目录，找到 .Report 和 .SemanticModel 子目录，加载 report.json 和 model.bim。convert_pdf_to_images 用 PyMuPDF 把 PDF 每页保存成 PNG。write_modified_zip 把改后的 JSON 写回，再重新打包成下载用的 zip。
  • 切片函数：extract_dashboard_by_page 把 sections[] 拆成每页一个对象、extract_relevant_parts_dataset 从 model.bim 抽出 tables + measures、extract_measures_name_and_expression 拍平 measure 的 DAX。
  • add_read_me 构造将要插到 sections[0] 的 README 节点。纯 JSON 操作，这里不调 Claude。
  • 每个 tab 跑之前先确认 "该有的东西都填了吗"：API key 是否填了、需要的文件是否上传了、Chat tab 的 XMLA 端点和认证字段是否齐了。
  • 锁定的模型 ID（claude-sonnet-4-6、claude-haiku-4-5-20251001）、默认语言、输出文件名、错误与成功提示文案。UI 里没有模型下拉框 —— 这是有意为之。
  • t(language, key) 查表函数，三种语言（English / French / Chinese）的 UI 文案一站式管理。
03 · Workflow

三个 tab，三条数据走向。

Documentation 和 README 走的是 "上传 → 解析 → Claude → 输出" 的批处理；Chat tab 多了一个 tool-use loop —— 整个系统最有意思的地方。

Documentation Workflow

从一个 PBIP zip 到一份完整 Markdown 文档，整个过程 Python 自动完成，用户只需要等。

1

用户在 sidebar 上传 PBIP .zip

同时选输出语言（English / French / Chinese），点 "Documentation" 按钮。

2

file_operator 解 zip

把 zip 解到临时目录，在里面找到 .Report/report.json 和 .SemanticModel/model.bim，加载成 Python dict。

3

json_operator 切片

把 report 按 page 拆开，把 model 按 table、measure 抽取关键字段（避免一次塞太多 token 给 Claude）。

4

Sonnet 4.6 分项总结

每个 page 单独调一次 call_text；table source 一次；measure overview 一次；detailed measure 一次。

5

再调一次做整体概览

基于所有 page 摘要，让 Claude 写一段 dashboard 的 high-level 概述。

6

拼成 Markdown · 提供下载

用多语言模板把所有片段拼成 Documentation.md，UI 端同时提供下载按钮和折叠预览。

README Workflow

多模态路径：Claude 同时看 JSON 数据和报告截图，最后把生成的 README 页面注入到 report.json。

1

用户上传 PBIP .zip + 报告 PDF

PDF 必须是这个报告的导出 —— 后面 Claude 要用它来"看"每个 page 长什么样。

2

PyMuPDF 把 PDF 转 PNG

convert_pdf_to_images 调 fitz.open(...).get_pixmap()，每页存成一张 PNG 到 Images/。

3

多模态摘要：JSON + 截图一起喂给 Claude

call_with_image 把 PNG 转 base64，自动识别 media type，跟 page JSON 一起作为一次 Sonnet 4.6 调用送出去。

4

二次提炼成 README 结构化文本

从每页的全文摘要里只抽出 "Page Overview" 和 "Visualizations"，丢掉 slicer / filter 之类的次要信息。

5

json_operator 构造 README 节点

add_read_me 拼出符合 Power BI report.json schema 的 README section，插到 sections[0]。

6

重新打包 · 提供下载

write_modified_zip 把改后的 JSON 写回原目录结构再重新压成 zip，用户下载后用 Power BI Desktop 打开就能看到新 README 页。

04 · 技术栈

每一块都尽量"无聊"，没有黑魔法。

只用业界常见的工具：Python 跑应用，Streamlit 做界面，Anthropic SDK 调 Claude，MCP SDK 通过 stdio 跟外部二进制讲话，PyMuPDF 处理 PDF。其余全是 Microsoft 生态既有的东西。

Python

3.11+ · 已在 3.14 测试

唯一的运行时。其它东西要么是 Python 包，要么是通过 stdio 跟它说话的外部进程。

Streamlit

Python web 框架

渲染 tabs、sidebar、文件上传、chat 输入框，并维护 chat history 的 session state。

Anthropic SDK

anthropic ≥ 0.40 · Python

调 client.messages.create，支持纯文本和多模态（base64 图片）。包装了 Sonnet 4.6 和 Haiku 4.5 两个模型。

MCP SDK

mcp ≥ 1.0 · Python

stdio client，用来跟 Power BI Modeling MCP Server 说话。打开 ClientSession、list tools、call tools 都靠它。

PyMuPDF

fitz · Python binding

把上传的 PDF 报告每页渲染成 PNG，给 README tab 的多模态 Claude 调用使用。

python-dotenv

.env 加载

从 .env 读 MCP_SERVER_EXE 路径 —— 这是唯一不通过 sidebar 输入的配置项。

Power BI MCP Server

.NET single-file · Microsoft 提供

从 microsoft/powerbi-modeling-mcp 下载的外部二进制。通过 XMLA 跟 Fabric 通信，对外暴露 8 个 tool，我们只用 7 个只读的。

Fabric XMLA

实时数据平面

真实的 Power BI 工作区和 semantic model。认证方式：interactive 浏览器登录（推荐）或 username+password。

Claude 模型

Sonnet 4.6 + Haiku 4.5

Sonnet 4.6 跑 Documentation / README（看重质量）；Haiku 4.5 跑 Chat（看重 tool-use 的延迟和成本）。

streamlit run streamlit_app.py
